# LMS Main Service (Learning Management System)

Добро пожаловать в репозиторий моего микросервиса для системы управления обучением (LMS). Это бэкенд-ядро, которое отвечает за управление курсами, главами (разделами) и уроками, а также за управление пользователями и безопасностью на основе JWT токенов. 

Я спроектировал архитектуру с упором на производительность, безопасность, модульность и чистый код, в точности следуя лучшим паттернам проектирования.

## 🚀 Стек технологий

- **Язык:** Java 21
- **Фреймворк:** Spring Boot (Web, Data JPA, Validation)
- **Безопасность:** Spring Security (OAuth2 Resource Server) + Keycloak
- **База данных:** PostgreSQL 
- **Миграции БД:** Liquibase (формат XML и SQL скриптов)
- **Маппинг:** MapStruct (для преобразования Entity <-> Java Records)
- **Утилиты:** Lombok (снижение бойлерплейта)
- **Документация API:** Swagger / OpenAPI 3 (с поддержкой Bearer JWT Auth)
- **Контейнеризация:** Docker & Docker Compose (для локального запуска БД и Keycloak)
- **Сборка:** Gradle

## 🏗 Ключевые архитектурные решения

В процессе разработки я применил ряд важных паттернов и подходов:

1. **JPA Auditing & BaseEntity:** 
   Я выделил общие поля (ID `Long`, дата создания, дата обновления) в родительский класс `BaseEntity` (помеченный аннотацией `@MappedSuperclass`). Spring JPA Auditing автоматически управляет этими полями при сохранении данных в базу. Отношения настроены с поддержкой `orphanRemoval = true` для обеспечения чистоты базы.

2. **IAM & Безопасность (Keycloak):** 
   Система использует Keycloak в качестве Identity and Access Management сервиса. Бэкенд интегрирован с Keycloak Admin REST API для регистрации пользователей и смены паролей. Защита эндпоинтов (например, `@PreAuthorize("hasRole('ADMIN')")`) настроена с помощью кастомного `JwtAuthenticationConverter`, который парсит роли напрямую из `realm_access` внутри JWT токена.

3. **Чистая Архитектура (DTO Records & Service Interfaces):**
   - Все DTO строго разделены на `CreateRequest`, `UpdateRequest` и `Response` и реализованы через **Java Records** для иммутабельности.
   - Сервисный слой работает исключительно через **Интерфейсы** (`CourseService`, `UserService`), а реализация скрыта в пакете `impl` (`CourseServiceImpl`), что обеспечивает низкую связность и легкое тестирование.
   - Контроллеры строго используют паттерн `ResponseEntity`.

4. **Global Exception Handling:** 
   Написан универсальный перехватчик ошибок `@RestControllerAdvice` (`ExceptionHandlerCustom`), который обрабатывает кастомное исключение `LmsException` в связке с `ExceptionStatus` (enum). Это позволяет клиенту всегда получать предсказуемый JSON-ответ с UUID ошибки и точным статусом.

5. **Оптимизация базы данных и Пагинация:** 
   Я активно использую `@EntityGraph` для борьбы с N+1 запросами при LAZY-загрузке. Также внедрен механизм `Pageable`, что позволяет получать данные порционно (например, `Page<CourseResponse>`).

## ⚙️ Как запустить локально

1. Склонируй репозиторий и перейди в папку с проектом.
2. Подними инфраструктуру (PostgreSQL и Keycloak) через Docker Compose. В процессе запуска Keycloak автоматически импортирует `realm-export.json` со всеми нужными ролями и дефолтным админом:
   ```bash
   docker-compose up -d
   ```
3. Собери проект при помощи Gradle:
   ```bash
   ./gradlew build -x test
   ```
4. Запусти приложение:
   ```bash
   ./gradlew bootRun
   ```
   *Liquibase автоматически накатит все нужные миграции (`001-create-tables`, `002-insert-data` и т.д.), так что вручную таблицы собирать не придется!*
